# Project memory

## Capture policy

Capture project memory in `.mstack/memory.md`. Read relevant memory before
work and record material decisions, facts, open questions and gotchas as they
arise. Distinguish confirmed decisions and observations from proposals,
uncertainty and unresolved discussion.

Keep an entry when it changes future work or supplies context for a future
decision. Link maintained specifications instead of copying them. Exclude
credentials, secrets and private material that does not belong in the project.

Memory is a concise continuity log. Current story specifications, workflow
facts and evidence belong in their maintained records; memory is not a
transcript, second backlog or substitute for verification.

## Maintenance

When reading memory, check for outdated or contradictory entries. Consolidate
duplicates and remove superseded claims once the current decision or fact is
established. If the correct conclusion is unresolved, mark the conflict and
the evidence or decision needed to resolve it rather than presenting both
claims as settled facts.

When a version-control conflict affects `.mstack/memory.md`, preserve entries
from both sides while reconciling. Do not discard an entry merely to choose
one side of the conflict. Then consolidate duplicates and reconcile
superseded or conflicting claims under the maintenance rule above.

Suggest promoting stable project guidance to the root `AGENTS.md`. After an
agreed promotion, remove duplicate detail from memory and link to the
maintained guidance where useful.
