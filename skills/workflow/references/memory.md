# Project memory

## Capture policy

memory is captured in the project file .mstack/memory.md

this file contains

Capture material decisions, facts, open questions and gotchas as they arise.
Distinguish confirmed decisions and observations from proposals, uncertainty and live conversations. when adding an entry to memory good questions to ask to validate if it should or shouldn't be remembered:

- is this a fact that would change our work in the project moving forward? 
- is this a memory that helps us add context to future decisions?

Link maintained specifications instead of copying them. Exclude credentials,
secrets and private material that does not belong in the project.

Memory is a concise continuity log. Current work specifications, workflow facts
and evidence belong in their maintained records; memory is not a transcript,
second backlog or substitute for verification.

## Maintenance

In order to keep durable project guidance in `AGENTS.md`, every time you go through memory, check if there are any entries in memory.md that are outdated and may generate inconsistencies across eachother. For entries that are stable as decisions are part of the project, you can openly suggest if they should be part of the `AGENTS.md` file in the root of the repo. if the answer is yes and you move them, you can then forget them from the memory.md.
